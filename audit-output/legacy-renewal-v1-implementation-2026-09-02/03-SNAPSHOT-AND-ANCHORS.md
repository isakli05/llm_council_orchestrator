# 03 — Snapshot & Anchors (STEPS 2–3)

Snapshot: single-pass `buildGuardedCopy` (denylist by NAME before any read: `.env*`/keys/credentials never opened; vendored/VCS dirs skipped; archives never expanded; binary/oversize excluded; symlink entries never followed; corpus caps → blocked with sizing guidance; `copy:false` mode for read-only status walks) produces the sorted sha256 manifest AND the LCO-owned workspace copy. `ProjectSnapshot` (schema v1): realpath + repo_kind git|plain + commit-when-available + file index + graphify version + stable manifest digest (mtime/seen projected out; empty-manifest constant). `snapshot_id` = digest over identity fields only → idempotent. Staleness codes: target_commit_changed | file_changed/added/removed (bounded lists) | graph_manifest_changed | graph_missing | graph_invalid.

Anchors: `EvidenceItemSchema` is now a strict union — kind `code_anchor` requires `{node_id?, path, content_hash, start_line?, end_line?}` with `hash === content_hash` (canonical: sha256 over raw bytes, no normalization; renames/deletes = file_missing). Pre-existing kinds forbid the anchor key → old bundles unchanged (regression-swept; `generated/spec-schema.json` regenerated by build). `AnchorVerifier` recomputes always; realpath containment (`isInside`, never prefixes); symlink escape → path_escape (in-repo links resolve — documented); traversal/absolute/backslash → invalid_path; directories refused; wrong project never verifies; seeded 25-round mutation loop green. Renewal evidence rule enforced downstream: unverifiable claims are rejected (recovery) or blocking (parity gate).
